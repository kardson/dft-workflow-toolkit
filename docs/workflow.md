# 通用协作与验证流程

## 分工

方法负责人确定科学问题、方法选择、歧义裁决和最终科学接受。实现负责人是同一路线的唯一写入者，连续完成批准范围内的准备、机械修正、定向验证与交付。共享管理变更由用户授权的管理写入者负责。

模型与推理设置由用户控制，不根据职责名称推断。不同计算后端各自维护来源、参数、环境和科学结论；能量与赝势环境不能跨后端或跨环境混用。

## 完整本地单元

一个单元包括准备、范围内机械修正、实际文件验证和可使用的交付。修正沿用同一单元 ID。缺失科学选择、来源变化、方法变化、重启变化或新增远端动作须由负责人裁决。

交接时给出：单元、目标、精确规格与来源、允许范围、实际交付、停止条件。默认采用消息驱动交接；交付后结束当前回合。持续监控、通知和等待须另有明确授权。

## 按风险验证

| 批次 | 最小验证 |
|---|---|
| 文案、导航、少量路径调整 | 链接或路径检查、相关文件审阅 |
| 局部解析或校验逻辑 | 相关单元测试与构造的失败样例 |
| 公共接口、配置、权限或重启契约 | 综合审阅、相关模块测试，按具体风险扩大范围 |
| 最终交付 | 一次整体审阅、一次覆盖本次变化的完整验证 |

不为每个小修正反复运行相同的全套检查。输入与相关工具未变时复用成功结果；出现新风险或实际失败后才扩大检查。哈希用于确认交付身份和完整性。

## 科学证据

优先读取实际输入与主输出，区分声明值和实际生效值。保留物种顺序、原子映射与约束；核对实际运行目录、环境与明确的 fresh/restart 契约。

准备完成不代表已经提交。进程返回 0 不代表收敛。主输出完整不代表科学接受。证据不足时报告 UNKNOWN 或 PARTIAL，并注明时间、来源与缺口。

具体材料、模型厚度、外场、收敛阈值、参照构型、科学假设和判断标准均属于使用者的私有研究方案，不放入通用流程文档。
