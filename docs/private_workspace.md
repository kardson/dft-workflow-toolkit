# 私有工作区结构

公开工具仓库与研究工作区分开维护。以下名称是示意目录，真实内容不进入公开 Git 历史。

```text
private-research/
  plan/          研究问题、想法与方法规格
  literature/    文献、批注、提取文本与索引
  models/        结构与模型谱系
  runs/          输入、输出、重启与执行记录
  analysis/      结果、图表和科学解释
  manuscripts/   论文、汇报与评审材料
  local-config/  私有环境与连接配置
```

工具以明确路径读取使用者指定的输入，并把结果写入私有工作区。公开仓库仅保存通用代码、空白记录和合成测试。不要把上述目录通过子模块、软链接或目录联接放入公开仓库。

私有工作区可以单独使用本地 Git 或访问受限的远端备份；是否上传、上传到何处，由拥有者另行决定。不能通过把公开仓库后来改成私有来追回已经公开的数据。

## 每次任务和结果如何组织

VASP工作区内，按研究主题建立任务，再把不同尝试分开保存。任务ID、尝试ID与实际执行ID分别记录，不能靠日期猜测对应关系。下面是可采用的目标约定；工具生成包的内部目录关系应保留，并先验证消费者适配。

```text
runs/<topic>/<task_id>/
  README.md
  task_manifest.json
  attempts/<attempt_id>/
    specification/              已批准规格及来源
    preparation/                候选包、生成与检查记录
    submitted/                  实际提交输入与运行包的冻结副本
    execution/                  实际启动、软件环境和执行回执
    returns/<collection_id>/
      raw/                      原样回收的输出
      receipt.json              回收范围与完整性记录
    checks/                     执行后检查与接受记录引用
    analysis/<analysis_id>/     单次分析、数据和诊断图
analysis/figures/<figure_id>/
  figure-record.json            图的来源和复现信息
  data/                         绘图数据
  scripts/                      脚本或操作步骤
  outputs/                      图文件
```

来源结构保留文献/父结构与坐标变换记录；优化结构留在产生它的任务中，接受后登记为可复用模型。运行诊断图留在任务旁，跨任务比较和正式图集中在analysis；图需连接到实际数据、处理步骤、设置与来源任务。历史图缺少数据或脚本时明确不可复现，不推测补齐。

原始输出和历史批准清单保持原样。重启来源、活动计算和通知仍使用的位置需先核实依赖，再迁移。迁移采用复制、核对、切换可编辑引用及最后归档；新旧路径记录在私有映射中。旧来源和失败记录保留，迁移成功不改变科学接受状态。参考文献、结构、实际输入输出、图表、映射和回执均属于私有研究数据。
